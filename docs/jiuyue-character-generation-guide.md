# 小狮子 × 非人哉：角色生成要求与踩坑记录

整理日期：2026-09-15  
适用项目：神仙摸鱼棋（小游戏）  
版本：v1  
关联运行文件：[games/jiuyue/index.html](../games/jiuyue/index.html)

本文根据此前小游戏生成聊天、裁剪返工记录、已保存的《狮子非人哉自走棋_开发规划.md》v2，以及本次实际读取的 GitHub 游戏代码整理。用于继续制作角色时继承已确认要求，避免重复返工。

**优先级：用户后续明确修改 > 本项目已确认的要求 > 本文整理的制作建议。**  
本文不代表所有资产都已逐帧验收，也不代表其余角色已生成完成。

## 1. 先记住这几个结论

1. 基底是用户已认可的“小狮子”，再融合《非人哉》角色特征；不能只剩狐狸、兔子或普通人形角色，也不能只画通用狮子而丢失角色特征。
2. 九月采用白色毛发、浅灰阴影、粉色耳内、红色外套版本，不沿用早期黄色狐狸方案。
3. 核心目标是稳定、连贯、能循环的角色动画；单张看着正常，不等于拼起来正常。
4. 裁剪统一画布、身体尺度、中心和脚底基线。不能每帧按非透明外接框紧裁后直接拼，也不能逐帧放大缩小来填满画布。
5. 九月现有单帧为 416×480，脚底基准约为左上角坐标系中的 (208, 440)；Idle、Move、Attack 各 5 帧。
6. Idle 的原始要求是 30 fps 时间轴、每张图停留 6 帧，即每张 200 ms，整轮 1 秒。Attack 后来修订为 100/100/200/200/200 ms，整轮 0.8 秒，不能全部套用同一帧时序。

## 2. 已确认的形象与表现要求

| 项目 | 要求 | 依据 |
|---|---|---|
| 基准造型 | 沿用用户已经认可的小狮子外形与比例 | 用户先指出“小狮子的形象怎么没了”，随后确认“对对对 按照这一版试试” |
| 角色辨识度 | 在小狮子上融合非人哉角色的配色、耳朵、发型、衣服和标志性配饰 | 用户反复强调“特征还是用非人哉的” |
| 九月配色 | 白毛、浅灰阴影、粉色耳内、红外套；狐耳、白尾等特征 | 开发规划 v2 和生成返工记录 |
| 边缘 | 轮廓要更明显，缩小到棋盘中仍能分辨 | 用户要求“边缘可以明显一点” |
| 视角 | 角色只绘制正面；不要求侧面、背面，不随敌人方向旋转整张角色图 | 开发规划 v2 已确定方向 |
| 背景 | 角色输出透明 PNG，保留实际 Alpha；白色背景不能视为透明背景 | 透明背景返工要求与现有资产规格 |
| 一致性 | 同一角色跨帧、跨动作保持实际大小、外形和关键特征稳定 | 裁剪返工、后续“不漂移”要求、开发规划 v2 |
| 移动 | 按格移动；角色可以原地迈步，实际位置由程序移动 | 用户的格子移动要求与开发规划 v2 |
| 攻击 | 可用贴图或向目标轻撞；远程创建独立飞行物，九月使用小火球 | 用户原始表现要求 |
| 后续角色 | 逐步扩充非人哉角色；先确认单张造型，再制作动作 | 已确认项目方向与开发规划中的制作顺序 |

“小狮子 + 非人哉特征”是两个同时成立的条件。只满足其中一个就需要返工。

用户要求的是轮廓清楚；当前记录不足以把其他项目的粗黑描边、暗黑童话、像素风或复杂材质禁令当成本项目的既定画风。

## 3. 帧规格与播放时序

### 3.1 当前九月规格

| 动作 | 帧数 | 单帧尺寸 | 每张持续时间 | 总时长 | 说明 |
|---|---:|---|---|---|---|
| Idle | 5 | 416×480 | 200/200/200/200/200 ms | 1 秒 | 首尾能衔接循环；对应 30 fps 时间轴每张停留 6 帧 |
| Move | 5 | 416×480 | 200/200/200/200/200 ms | 1 秒 | 现有代码按每张 0.2 秒播放；规划要求连续迈步，不每走一格重置 |
| Attack | 5 | 416×480 | 100/100/200/200/200 ms | 0.8 秒 | 第 3 张开始，约 0.2 秒时触发攻击事件 |

- “5 张图，每张停留 6 帧”是 30 个时间轴帧，不是生成 30 张不同图片。
- 攻击的前两张，在 30 fps 时间轴上各停留 3 帧；后三张各停留 6 帧，总计 24 帧。
- 现有渲染代码按横向精灵表从左到右读取，每张源区域为 416×480，横向偏移为帧索引 × 416。对应排布为 5 列 × 1 行。
- 原始生成大图的排布不能凭空假定为相同格式；导出时再转换为运行时需要的规格。
- Idle 明确要求首尾循环；Attack 是一次完整出手与收招，不应机械要求首尾画面重复。
- 渲染刷新率、逻辑更新频率、素材帧停留时间是不同概念，应分别记录。

### 3.2 锚点和显示尺度

- 当前九月的脚底基准约为 **(208, 440)**，坐标原点为每张 416×480 画布的左上角。
- 用脚底定位到格子中心，不用非透明外接框的中心定位。
- Idle、Move、Attack 使用相同尺度和脚底锚点，切换时不应突然长高、缩小或偏移。
- 当前代码按宽度 112 绘制，缩放系数为 112/416，并用 440 × 缩放系数确定脚底偏移。112 是当前实现值，不是未来所有视口下的强制像素尺寸。
- 长耳、角、飘带、尾巴会改变外接框。统一尺度应看脸、身体和脚底，不能把“含配饰总高度”强行统一。
- 给配饰留足透明空间；若新角色确实需要更大画布，应同步调整元数据和渲染裁切，不能悄悄缩小整个人物。

## 4. 已实际发生的返工与教训

| 问题 | 找到的记录 | 处理原则 |
|---|---|---|
| 非人哉特征丢失 | 用户强调“特征还是用非人哉的！就是九月形象的小狮子，小玉形象的小狮子” | 生成前同时锁定小狮子基底和角色识别点，不能只写“可爱动物” |
| 小狮子形象丢失 | 用户反馈“小狮子的形象怎么没了”，后续才认可修订版 | 以用户认可的图片作为参考，不退回此前被否定的设计 |
| 九月被画成黄色狐狸 | 检索到白色配色、不要黄色狐狸的返工要求 | 使用现有白毛红外套版本；不要继承早期设定图错误配色 |
| 背景不符合透明要求 | 检索到要求重新使用透明背景的反馈 | 检查实际 Alpha；白底、棋盘格图案都不能代替透明像素 |
| 裁剪后高度忽高忽低 | 用户：“为什么高度差这么多，示例图里面的高度我看挺正常的啊” | 统一画布、角色中心、脚底基线，禁止独立紧裁后直接拼接 |
| 动画仍有漂移顾虑，需要重做 | 后续用户要求“重新生成，然后做成5帧动画我看看，尽量保证角色不漂移” | 必须看循环播放效果，不能只交一张五帧排版图 |

### 4.1 裁剪问题的具体记录

2026-09-15 17:12～17:13（北京时间）检索到的返工聊天中，助手当时解释：

- 对每一帧的非透明内容分别取 bounding box；
- 结果每帧画布高度或脚底位置不同；
- 拼接成动画后出现“忽高忽低”和漂移；
- 应改成所有帧共用画布，统一脚底基线和角色中心，不逐帧缩放到画布。

这是**当时助手记录的原因**。本次未取得当时那份裁剪脚本并重放，不能把它表述成已经重新复现的代码结论。

外接框可用于检测裁切、空白边距和异常，不应直接成为每帧的最终画布或独立缩放依据。如果生成图本身已经发生头身比例变形，单纯移动画布无法修复，应返工对应帧。

### 4.2 容易继续踩的坑：属于防错建议，不冒充已发生事故

- 动作之间使用不同缩放系数，导致切换时角色跳变。
- 把头部呼吸、手臂运动全部对齐消除，虽然位置稳定，却把动作也抹掉。
- 将长耳、角等配饰纳入“总高度一致”缩放，让不同角色身体忽大忽小。
- 将整张正面图旋转去朝向敌人，破坏纸片立牌式表现。
- 把火球画进每帧角色图，导致弹道无法独立控制、替换或复用。
- 把 GIF 当游戏逻辑时钟，导致命中与动作脱节。
- 仅凭生成图片标题写着“透明”或“精灵图”，就宣称已符合技术规格。

## 5. 动画与战斗接入要求

这些内容主要来自已有开发规划，后续接入时需要验证，不能仅因为写进规划就声称已全部实现。

1. 角色保持正面。攻击方向通过弹道、轻微前冲、目标标记和命中特效表达。
2. 相邻格之间用位置插值；落点仍在格子中心。迈步动画与跨格计时分开，避免每走一格从第一张重新播放。
3. 第三张攻击图开始时触发一次攻击事件。近战在该时刻结算命中；远程在该时刻生成火球，飞到目标后才扣血。
4. 一个攻击周期只触发一次，不因同一张图片显示多次而重复扣血或重复发射。
5. 前冲只作用于绘制偏移，不改变逻辑格子和占用。
6. 受击先用闪白、死亡先用淡出，无需立刻扩充受击和死亡动画。
7. 火球等可使用单张透明贴图，由代码控制飞行；这属于素材制作策略，不代表仓库已经有独立火球 PNG。
8. 游戏内使用 PNG 精灵表，GIF 仅作预览。
9. 头像和商店图可以从 Idle 提取；UI 需要独立限制显示宽高，不能继承整张角色图尺寸。

## 6. 后续制作流程与验收建议

本节是根据以上要求整理的工作方法，不是对未找到的历史操作步骤的补写。

### 第一步：确认参考图

使用用户最终认可的基准图，并记录其文件名、版本、角色配色、衣服与标志性配饰。仅凭文字摘要不足以精确复刻脸型与比例；参考图片不在手边时，先找回实际图片再生成。

本次归档没有新增或复制角色原图。现有游戏内 Idle 可提取为九月运行资产参考，但不能把它自动称为最初获批的完整角色设定图。

### 第二步：生成动作

先做一个角色的一组 5 帧并查看效果，再批量扩展。动作幅度要服务于连贯性，避免跨帧换脸、身体整体缩放或衣服配饰突变。Idle 保证循环衔接；Attack 保证蓄力、出手、收招完整。

### 第三步：整理画布

统一画布、尺度和锚点，保留透明留白。允许为修正非动作性漂移进行对齐，但不通过独立拉伸或缩放每帧去强行填满格子。对齐脚底时保留自然迈步、呼吸和手臂动作。

### 第四步：交付播放预览

按真实时序播放，至少观察数轮 Idle/Move 和多次 Idle→Attack→Idle 切换。除了单帧检查，也要在棋盘目标显示尺寸下观察轮廓、脚底、比例与动作节奏。

### 验收清单

- [ ] 仍能辨认出已认可的小狮子基底和对应非人哉角色。
- [ ] 九月保持白毛、浅灰阴影、粉耳内、红外套版本。
- [ ] 每组正好 5 帧，顺序明确；运行时导出符合 416×480 单帧规格。
- [ ] 实际背景透明，边缘没有明显残留底色。
- [ ] 没有角色整体忽大忽小、无意义平移或脚底基线跳变。
- [ ] 没有裁掉耳朵、尾巴、手脚、衣服等部位。
- [ ] 配饰变化没有导致身体比例被强制缩放。
- [ ] Idle 首尾循环自然，Move 连续播放自然。
- [ ] Attack 使用 100/100/200/200/200 ms，出手事件与第三张开始一致。
- [ ] Idle/Move/Attack 切换时大小和锚点一致。
- [ ] 棋盘中缩小播放仍清楚，头像/商店图尺寸独立受控。
- [ ] 预览、单帧、精灵表和时序元数据能够对应。

这些是待执行的验收项，本次文档归档没有逐项重新测试素材。
