对象池解决什么问题

游戏里有很多对象会频繁创建和销毁：

子弹
伤害数字
飘字
命中特效
掉落物
音效播放器
UI 列表项
怪物预制体

普通写法：

GameObject bullet = Instantiate(bulletPrefab);
Destroy(bullet);

偶尔一次没问题，但如果每秒几十次，会带来：

CPU 开销
内存分配
GC 压力
卡顿
资源加载抖动

对象池的思路是：

不用了不要销毁，先放回池子。
下次要用，再从池子里拿出来复用。

核心结构

对象池常用 Stack<T> 保存空闲对象：

Stack<GameObject> pool = new();

原因是对象池通常不关心顺序：

拿哪个空闲对象都行。

Stack.Push 和 Stack.Pop 很适合：

回收时 Push
取出时 Pop

取对象

GameObject Get()
{
    if (pool.Count > 0)
    {
        GameObject obj = pool.Pop();
        obj.SetActive(true);
        return obj;
    }

    return Instantiate(prefab);
}

逻辑：

池子里有空闲对象：
    拿一个出来，激活，返回

池子里没有：
    创建一个新的

回收对象

void Release(GameObject obj)
{
    obj.SetActive(false);
    pool.Push(obj);
}

逻辑：

不用了：
    先隐藏
    放回池子

这里不是 Destroy，而是复用。

简化版对象池

public class SimpleGameObjectPool
{
    private readonly GameObject prefab;
    private readonly Stack<GameObject> pool = new();

    public SimpleGameObjectPool(GameObject prefab)
    {
        this.prefab = prefab;
    }

    public GameObject Get()
    {
        if (pool.Count > 0)
        {
            GameObject obj = pool.Pop();
            obj.SetActive(true);
            return obj;
        }

        return UnityEngine.Object.Instantiate(prefab);
    }

    public void Release(GameObject obj)
    {
        if (obj == null)
        {
            return;
        }

        obj.SetActive(false);
        pool.Push(obj);
    }
}

使用：

SimpleGameObjectPool bulletPool = new(bulletPrefab);

GameObject bullet = bulletPool.Get();

// 子弹飞完或命中后
bulletPool.Release(bullet);

坑一：取出时要重置状态

对象复用前一定要清理旧状态。

例如子弹上次的数据：

速度 = 20
伤害 = 100
目标 = enemyA
已经命中 = true

如果回收后下次直接拿出来，不重置，就可能：

新子弹一出生就处于“已经命中”
新子弹还保留旧目标
新特效还带着旧颜色、旧位置、旧回调

所以对象池通常会有：

OnSpawn：取出时初始化
OnDespawn：回收时清理

示例：

public interface IPoolable
{
    void OnSpawn();
    void OnDespawn();
}

坑二：防止重复回收

如果同一个对象被回收两次：

pool.Release(bullet);
pool.Release(bullet);

池子里会有两个相同引用。

之后两次 Get() 可能拿到同一个对象：

A 拿到 bullet
B 也拿到 bullet

这会非常难查。

可以用 HashSet<GameObject> 检测：

HashSet<GameObject> inPool = new();

回收时：

if (!inPool.Add(obj))
{
    Debug.LogWarning("重复回收");
    return;
}

obj.SetActive(false);
pool.Push(obj);

取出时：

GameObject obj = pool.Pop();
inPool.Remove(obj);
obj.SetActive(true);

这里用到了 HashSet.Add 的返回值：

false 表示已经存在，说明重复回收。

坑三：对象池不是越大越好

对象池减少创建销毁，但也会占内存。

如果池子里长期堆着大量不用的对象：

不销毁也会占内存。

成熟对象池通常会有：

初始容量
最大容量
超出最大容量时 Destroy
长时间不用时裁剪
场景退出时清空

例如：

if (pool.Count >= maxSize)
{
    UnityEngine.Object.Destroy(obj);
    return;
}

适合对象池的场景

适合：

创建销毁频繁
对象结构差不多
生命周期短
复用成本低

例如：

子弹
特效
伤害数字
UI 列表项
音效播放器

不适合：

很少创建的对象
状态极其复杂且难以重置
长期存在的唯一对象

最重要的收获

对象池用“回收复用”替代“频繁创建销毁”。

最重要的三个坑：

取出时要初始化。
回收时要清理。
防止同一个对象重复回收。

和前面知识点的连接：

Stack：保存可复用对象。
HashSet：检测重复回收。
生命周期管理：谁 Get，谁 Release。
状态重置：避免旧数据污染新对象。
