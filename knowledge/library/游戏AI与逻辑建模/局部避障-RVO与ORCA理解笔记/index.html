先记住它解决什么问题

NavMesh 和 A Star 解决的是：

从哪里走到哪里。

Funnel 算法解决的是：

在 NavMesh 多边形通道里，拉出一条更自然的路径。

RVO / ORCA 解决的是：

角色沿路径移动时，附近也有别的角色，怎么实时避让。

它不是全局寻路算法，也不是交通规则系统。

它更像局部移动层：

我下一小段时间应该用哪个速度移动，才更不容易撞到附近单位。

改速度不只是改快慢

容易误解的一点是：

改变速度是不是只改变跑得快慢？

不是。

这里的速度是速度向量：

velocity = direction * speed

它同时包含：

方向
大小

所以 RVO / ORCA 改速度，其实也在改移动方向。

例如原本想往右走：

desiredVelocity = (1, 0) * 3

避障后可能变成：

newVelocity = (0.8, 0.3) * 2.6

这表示：

稍微向右上方绕开。
同时速度略微降低。

表现层再根据 newVelocity 转向。

它为什么能提前避让

如果只判断当前有没有碰撞，发现时通常已经晚了。

RVO / ORCA 关心的是：

如果我继续用某个速度移动，未来几秒内会不会和附近单位重叠。

会导致碰撞的速度会被视为危险速度。

局部避障要做的是：

避开危险速度。
从安全速度里选一个最接近原本期望速度的。

所以它不是直接把角色推开，而是在选择：

下一帧、下一小段时间应该往哪个方向、以多快速度走。

RVO 和 ORCA 的直观区别

RVO 的意思是 Reciprocal Velocity Obstacles。

它的核心直觉是：

双方共同承担避让。

例如两个角色迎面走：

A --->     <--- B

不是 A 完全让，也不是 B 完全让，而是：

A 稍微偏一点。
B 也稍微偏一点。

ORCA 可以先粗略理解成 RVO 的工程化版本。

它把避障要求变成速度空间里的约束：

哪些速度不能选。
哪些速度可以选。
在可选速度里，哪个最接近期望速度。

开阔地里的图解

开阔地时，RVO / ORCA 比较适合：

A --->           <--- B

继续直走会撞。

避障后：

A --\             /-- B
     \           /
      \         /

这里空间足够，双方都稍微调整速度方向，就能绕开。

左侧有墙时的问题

如果左侧是墙：

墙
|
|   A --->        <--- B
|

如果只考虑角色之间的互相避让，可能会产生错误直觉：

A 往左偏一点。
B 也往左偏一点。

但左侧是墙，左偏可能撞墙或贴墙卡住。

所以局部避障不能只考虑 agent-agent，还要考虑：

墙体
NavMesh 边界
静态障碍物
角色半径

墙壁应该限制可选速度：

左侧速度不可选。

剩下的选择可能只有：

向右绕
减速
停止
后退

窄路时 RVO / ORCA 不够

如果两侧都是墙：

墙 |  A --->     <--- B  | 墙

这时可能没有足够空间让两个人同时绕开。

问题就不再是：

怎么各自挪半个身位。

而是：

谁先过？
谁等待？
谁后退？
要不要重新寻路？

这属于更上层的通行管理。

常见做法：

通道预约
优先级
等待点
单向通行规则
超时重新寻路
物理碰撞兜底

可以把窄路当成一个资源：

[入口] ==== 狭窄通道 ==== [出口]

它有状态：

Free：没人使用。
Reserved：有人预约。
InUse：有人正在通过。
Cooldown：刚用完，短时间内不让别人抢。

如果 A 已经获得通行权：

A 继续通过。
B 在入口等待。

现在的分层理解

可以先按这几层记：

NavMesh：哪里能走。
A Star：从起点到终点经过哪些区域。
Funnel：把多边形通道拉成自然路径。
RVO / ORCA：开阔区域里，实时选择安全速度向量。
墙体 / NavMesh 边界：限制哪些速度不能选。
通道预约 / 优先级：窄路里决定谁先过。
物理碰撞：最后防止真的穿模重叠。

最重要的收获

RVO / ORCA 的作用不是：

保证任何情况下都绝不相撞。

而是：

在局部范围内，预测未来碰撞，并选择一个更安全的速度向量。

这个速度向量同时决定：

移动方向
移动快慢
转向趋势

但在墙边、窄门、走廊、桥梁、双向队伍对冲时，只靠 RVO / ORCA 不够。

这类场景要加：

静态障碍约束
通行权
等待队列
重新寻路

一句话：

RVO / ORCA 解决“空间够时怎么绕”。
通道规则解决“空间不够时谁先走”。
