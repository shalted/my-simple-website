# 工程设计

这个分类用于整理工程设计中的核心思维：生命周期管理、所有权边界、缓存策略、异步请求合并、模块职责划分、错误恢复和可维护性设计。

## 先建立总模型

工程设计不是模式数量，而是让状态、责任和失败都可追踪。先明确权威数据和所有者，再定义正常路径、异步晚到、取消、重试与清理，最后才讨论抽象和性能。

### 一条跨模块状态链

```text
输入技能 -> 预检 Mana 100 >= 30
提交后 Mana=70 -> 创建运行实例 501
Timeline 在 0.3 秒生成投射物
命中后应用 Effect，并发布 HealthChanged
实例结束 -> 清理标签、订阅和资源作用域
```

## 推荐顺序

1. 从对象池、事件系统和资源生命周期开始。
2. 再看技能、Effect、状态仲裁和战斗判定的完整链路。
3. 学习缓存、配置、网络与异步一致性。
4. 最后进入 ECS、UE Gameplay、UI 绑定和 Timeline 等系统边界。
