## CHAPTER 07 · 当前技术树与待学习优先级

当前能力更偏向 **Unity 客户端工程落地、业务系统开发、编辑器与内部工具、Debug、资源与构建流程**。下一阶段的目标不是横向增加更多语言，而是把已经长期使用的 C# / Unity 工程经验继续向语言原理、测试验证、性能分析和通用软件工程能力深化。

### P0 · C# / .NET 本体深化

状态：待学习 / 待深化，最高优先级。

- `async` / `await`、`Task`、`CancellationToken` 的状态流、异常与取消传播。
- 泛型约束、协变与逆变，以及泛型在框架接口设计中的实际用途。
- 委托、事件、Lambda、闭包的运行机制与常见生命周期问题。
- 值类型、引用类型、装箱 / 拆箱、参数传递与复制语义的进一步深化。
- `IDisposable`、资源所有权与托管 / 非托管资源释放边界。
- GC、托管堆、分配来源，以及 Unity 中常见 GC Allocation 的定位与规避。
- LINQ 的执行方式、延迟求值、枚举器和常见性能成本。
- Reflection、Attribute 与编辑器 / 框架工具中的实际使用场景。
- `Span<T>`、`Memory<T>` 等低分配数据访问方式，先理解用途和使用边界。
- 线程基础、`lock`、线程安全集合与常见并发错误；已有原子操作与内存屏障知识作为后续深化基础。

目标：从“长期使用 C# 完成功能”提升到“能解释语言机制、判断运行时代价，并能设计稳定的通用接口”。

### P0 · 测试、Benchmark 与验证体系

状态：待学习，最高优先级。

- Unit Test、Integration Test 的职责边界和测试粒度。
- Unity Test Framework 的 EditMode / PlayMode 测试与适用场景。
- 为 Bug 修复建立最小复现、边界样例和回归测试，减少“修当前问题、引入周边问题”。
- Mock / Fake / Test Fixture 的基本用途，学习如何隔离复杂依赖。
- 建立可重复的性能 Benchmark：固定场景、固定数据、采样指标和修改前后对比。
- Unity Profiler、Memory Profiler、Frame Debugger 与 RenderDoc 的系统化使用路径。
- 将编译、测试、资源检查、静态检查与性能基线逐步接入 CI / Jenkins，形成自动验证闭环。
- 学习日志、指标、错误上下文和可观测性设计，让问题能够稳定复现和定位。

目标：把目前依赖人工自测和经验判断的部分逐步变成可重复、可量化、可自动执行的验证流程。

### P1 · 计算机基础从“看过”到“能用于排查”

状态：已有文章，待深化与工程化。

- 内存、堆、栈、虚拟内存、页与 GC：重点联系 Unity 内存和资源问题。
- 原子性、可见性、线程同步和内存序：从概念理解进一步连接到真实并发 Bug。
- 网络基础：TCP / UDP、连接状态、延迟、重传、序列化和客户端常见网络问题。
- 常见数据结构和复杂度：不追求刷题数量，重点学习如何根据数据规模选择结构。
- 缓存、对象生命周期、资源生命周期：结合现有资源加载、YooAsset、AB 和 UI 系统继续深化。

目标：遇到性能、内存、资源、并发或网络问题时，能够从底层机制形成可验证的排查假设，而不是只依赖试错。

### P1 · 通用软件工程与跨语言能力

状态：按实际项目需要补充，不追求语言数量。

- Python：继续围绕自动化脚本、数据处理、CI / 构建工具和问题分析深化。
- JavaScript / Node.js：围绕现有知识网站的构建管线、浏览器交互和 Cloudflare Worker 继续补工程实践。
- REST API、认证、数据库事务和基础后端设计：以能够理解和维护小型服务为目标。
- 了解 .NET 与 Python / Native Library 的互操作方式，作为未来工具链和 AI 工程可能用到的连接能力。
- 分布式系统只做基础认知：一致性、重试、幂等、消息队列和故障边界，不作为当前主线。

目标：保持 Unity / C# 主线，同时具备处理工具、服务和跨语言工程问题的基本能力。

### P2 · Unity 性能与渲染专项深化

状态：已有实践，按项目继续深化。

- URP 渲染流程、SRP Batcher、GPU Instancing、DrawCall / SetPass 与移动端 GPU 性能分析。
- Shader Variant、材质与资源加载之间的体积、内存和运行时代价。
- ComputeBuffer / GPU 数据布局、Instanced Procedural 等大规模渲染方式的适用边界。
- Overdraw、透明、后处理、阴影和移动端带宽问题。
- 建立“功能效果 → Profiler 数据 → GPU / CPU 瓶颈 → 优化验证”的完整渲染排查流程。

目标：把已有草地、Shader 和性能优化经验整理为稳定的方法论，而不是只解决当前项目中的单点问题。

### 暂不作为主线

- 不为了“技能数量”专门学习 Java、Go、Rust。
- C++ 保持基础学习，用于理解 UE、底层和 Native 代码；只有正式转向 UE / 系统开发时再提高优先级。
- AI / ML 模型训练暂不作为主线；当前更适合从 AI 工具使用、评测、工程集成和自动化切入。
